# 作品紹介

## コンセプト
- データの軽量化
  - XYN-MotionStudioはリアルタイムにモーションキャプチャーできるが、データにはすべてのジョイントに毎秒60フレームでキーフレームを打ちこむので大容量のデータになる
    - インゲームで利用できるアセットとして、モーションデータのキーフレームを最適化するようなスクリプトがあると、MAYAにインポートした後の編集作業が楽になる
- MAYAの理解
  - MayaのスクリプトはMELやPythonを使って実装されるが、ネット上にはガワとロジックが適切に切り分けられていないようなスクリプトも多いと感じた
  - QtCreatorを使った商用アプリケーション開発の経験もあったので、MAYAのシェルフ登録の問題を解決できるようなPySideのツールを作ろうと考えた

## 技術詳細
- OS

- バージョン管理
    - Github, SourceTree

## イチオシ
- 最適化が実行されたすべてのパーツでフィルタ適用前後がわかる
- initファイル配置による `sys.path` 管理の簡略化
- モーションデータの前処理を目的としたツール開発
  - XYN-MotionStudioのモーションデータをインゲーム向けに加工する
- GUIとロジックが適切に分離している設計
  - SpriteStudioやAtomCraftのQt開発経験を活かしたGUI構築
  - 相対インポートと絶対インポートを使い分けてランチャーを実装
- ブランチ戦略やコーディング規約を遵守
  - 再利用性が高く、堅牢なコードを記述する

  - 命名規則(キャメルケース): クラス名, 変数名

  - 定数 : すべて上部で定義

  - GithubAction: やるなら静的解析??

## 使用方法
1. キーフレームの最適化が必要なモーションデータを準備します。
　そのままのモーションデータでは総キーフレーム数が多いためMayaで手直しします。
　(XYN-MotionStudio -> モーションキャプチャ -> 地滑りを修正 -> FBXでエクスポート)
2. 本ツールを用いてキーフレーム最適化を行います。
　今回実装したキーフレーム最適化ツールは、最終的な削減数をログから確認できます。
　検証時には[root:17133→3154]のように約8割のキーフレームが削減されたことが確認できます。
　(Maya -> FBXをインポート -> 本ツールで最適化 -> HumanIKにリターゲット -> FBXでエクスポート)
3. モーションデータをアセットとして利用します。
　任意のモーションデータをゲームに組み込むことが可能になりました。
　(Unity -> FBXをインポート ->前処理で HumanoidRigに変換 -> AnimationClipとして活用)
